# Lyrion Display v0.3.0 — release candidate acceptance

**State: release preparation only — NOT published or submitted to F-Droid.**

Source on `main` includes PR #25 (Now Playing content options, automatic settings persistence, and fast return), plus the QA and F-Droid signing preparation from PRs #23, #24 and #26.

## Required hardware validation

Install the **production-key-signed v0.3.0 RC** over an installed signed v0.2.0 APK. Do not uninstall first; this tests the upgrade and retained settings.

- [ ] Check Android version **0.3.0**, versionCode **9**, and title **Lyrion Display**.
- [ ] Previously configured server, player, theme, color, keep-awake and display behavior persist through the upgrade.
- [ ] All four Now Playing options: playback progress, technical details, playlist position, original Material clock; verify each enabled and disabled.
- [ ] Clock updates over time and layout remains correct (especially Fire TV's narrower viewport). Album artwork, toolbar visibility and gear overlay remain intact.
- [ ] Settings auto-save changes without Save/Cancel; Home interruption or app restart retains valid preferences.
- [ ] Invalid/unfinished server edits do not overwrite the last working server/player; changing server then selecting a valid player saves the pair together.
- [ ] Back from Settings returns promptly to the existing Now Playing WebView when settings are unchanged, with no “Connecting to Lyrion…” overlay.
- [ ] Content appearance changes apply on return. Theme/player changes reload as required; changing servers reconnects safely.
- [ ] Remote D-pad, Menu, gear overlay, Back, keep-awake, and Material Skin playback updates all work.
- [ ] Fire TV launcher icon and TV banner remain correct, including after restart when practical.

## Publication boundaries

- Do **not** create tag `v0.3.0`, branch `publish/v0.3.0`, or a GitHub release before hardware acceptance.
- F-Droid metadata remains a **disabled** QA snapshot. It must not be silently activated by the version bump.
- Only after published GitHub v0.3.0 has been independently reproduced in the target F-Droid build environment should official F-Droid submission be considered.
- F-Droid submission must use a **separate manually triggered workflow**, never tag/push automation.
